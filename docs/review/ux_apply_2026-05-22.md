## Verification

- **App TypeScript type-check:** clean.
  `npx vue-tsc --noEmit -p tsconfig.app.json` → `EXIT=0`, no output.
- **Build-mode type-check:** the only diagnostic from `vue-tsc --build --force`
  is in `vitest.config.ts` — a pre-existing Vite 8 / Rolldown 1.0 vs Rollup 4
  plugin-type mismatch that is unrelated to anything changed in this round.
  `EXIT=0`.
- **Unit tests:** not run in this sandbox. The vendored `node_modules` was
  populated on Windows; native binaries for `esbuild`, `rollup`, and similar
  don't match Linux, so `vitest` can't start the Vite config loader. On the
  user's actual dev box (`pnpm install` on Linux/macOS), tests run normally.
  No test files were touched and no public interfaces of the changed
  components changed shape, so existing tests should continue to pass.

## Open items inherited from the brief

- `goa-microsite-header`'s `feedbackurl` is a placeholder mailto. Wire to the
  real ticket form once it's published.
- `goa-footer` slot links to `/privacy`, `/accessibility`, `/disclaimer` are
  placeholders; routes need to be added or links retargeted.
- `goa-work-side-menu` in v2.2.0 may render group headings differently than
  assumed; visual verification on the running app is needed and the markup
  uses slotted children consistent with the documented v2 pattern.
- `goa-container`'s `heading` prop is used for built-in section labels. If
  v2.2.0 of `@abgov/web-components` exposes a different prop name, the
  internal `<h2>` falls through naturally — the visual hierarchy still reads
  correctly with the explicit headings used in `ProfileView` and the new
  Dashboard tab bodies.
